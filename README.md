# FPGA Dino Game

A Verilog HDL implementation of the Google Chrome offline Dino game for the Zhejiang University Digital Logic Design course project.

The design runs on the **Sword Kintex-7 FPGA platform (Part: xc7k160tffg676-1)** and uses **PS/2 keyboard input**, **VGA 640×480 video output**.

## Features

* 640×480 VGA game display with RGB444 output
* PS/2 keyboard control
* Idle, playing, paused, and game-over states
* Dino jump, duck, fast-fall, run animation, and death pose
* Random cactus, pterodactyl, and cloud generation using an LFSR-based random system
* Ground scrolling with two alternating ground sprites
* Multi-slot obstacle motion system
* Approximate multi-rectangle collision detection
* Score counting with speed increase over time
* Day/night cycle and moon phase display
* Buzzer output for jump, hit, and score-reached events
* Simulation and board-verification files for key modules

## Controls

| Key             | Function                                    |
| --------------- | ------------------------------------------- |
| `Space` / `Up`  | Start the game or jump                      |
| `Down`          | Duck on the ground; fast-fall while jumping |
| `P`             | Pause / resume                              |
| `RSTN` on board | Reset the whole system, active low          |

## Target Platform

* FPGA board: Sword Kintex-7 experimental platform (Part: xc7k160tffg676-1)
* Development tool: Xilinx Vivado
* HDL: Verilog HDL
* Main clock: 100 MHz board clock
* VGA mode: 640×480 @ 60 Hz
* Pixel clock: generated internally by dividing the 100 MHz clock to about 25 MHz

## Design Overview

The project is divided into two main layers.

### Game Logic Layer

`src/game_logic/dino_game_logic.v` computes game state and object state. It does not generate pixels directly. Its main responsibilities are:

* PS/2 scan-code reception and key-event decoding
* Main game finite-state machine
* Dino jump, duck, animation, and fast-fall control
* Random obstacle/cloud generation
* Ground, cactus, pterodactyl, and cloud motion
* Collision detection
* Score and speed control
* Day/night and moon-phase state generation
* Sound-event trigger generation

All game state updates are synchronized by the `frame_end` pulse generated by the VGA controller. This prevents object coordinates from changing in the middle of a displayed frame.

### Display and Sound Layer

`src/display/display_system.v` renders the game state into VGA pixels and drives the buzzer. It does not modify the game state. Its main responsibilities are:

* VGA 640×480 timing generation
* Sprite ROM reading from `.mem` files
* Region detection for dino, obstacles, clouds, ground, and moon
* Transparent-pixel handling
* Pixel-priority composition
* Score, pause, and game-over overlay generation
* Day/night color transformation
* Buzzer waveform generation

## Building in Vivado

One possible Vivado workflow is:

1. Create a new RTL project.
2. Add all Verilog files under `src/`.
3. Add all `.mem` files under `assets/rom/` as memory initialization files.
4. Add `constraints/sword_dino.xdc` as the constraint file.
5. Set `top` in `src/top.v` as the top module.
6. Run synthesis, implementation, and bitstream generation.
7. Program the Sword Kintex-7 board (Part: xc7k160tffg676-1).

The sprite ROM module uses `$readmemh` with file names such as `dino_default.mem` and `ground_a.mem`. Make sure Vivado can find the `.mem` files during synthesis.

## Simulation and Verification

The `sim/` directory contains testbenches, board-verification top modules, constraint files, and waveform screenshots.

| Directory                   | Purpose                   |
| --------------------------- | ------------------------- |
| `sim/ps2_verify/`           | Verifies PS/2 byte reception, scan-code parsing, key hold states, and single-cycle trigger pulses |
| `sim/state_machine_verify/` | Verifies idle, play, pause, game-over, restart, and collision transitions                        |
| `sim/motion_verify/`        | Verifies ground scrolling, cactus slots, pterodactyl slots, cloud slots, and animation updates     |

Simulation and board-test images are stored under `sim/*_verify/img/`. These images are intended to support the course report and make the verification process easier to inspect.

## Asset and Tool Notes

The image assets are converted into 2-bit-per-pixel `.mem` files and loaded by `sprite_rom.v`. The script `tools/png_to_mem.py` is used for converting PNG sprites into ROM initialization data.

The repository also includes reference sound assets under `assets/sounds/`. The hardware implementation does not play MP3 files directly; instead, it generates simple buzzer waveforms for jump, hit, and score-reached events.
